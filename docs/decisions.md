# Рішення та відкриті питання

Створено: 2026-11-11. D-001/D-002, D-009 і D-010–D-021 — прямі відповіді власника
в чаті 2026-11-11. Решта базових вимог перенесена з наданого ТЗ v4; числові
defaults не є новими побажаннями власника. Стислий контекст розмов і поточний
стан робіт — у [context.md](context.md).

Термін: **цільовий канал** — елемент `target_channels` у конфігурації, тобто
власний Telegram-канал публікації з усіма своїми джерелами й правилами.
У ТЗ v4 і частині документів це саме поняття називалося «профіль».

### Уточнення 2026-11-11 після першої публікації

Ручне вікно з D-029 вище замінено D-031; довжину 1–2 речення з D-025 замінено
D-032. Попередні формулювання залишені як історія рішень.

| ID | Рішення | Наслідок |
| --- | --- | --- |
| D-031 | Ручний запуск бере останній завершений інтервал із schedule | Пряме уточнення власника: перший запуск о 21:31 за розкладу 08/15/21 бере **15:00–21:00**. Замінює кінець «зараз» і початок «найближча минула межа» в D-029. Початок додатково обмежений `scan_start_at` і вже покритим із БД/стану; запит до запущеного worker та захист від повтору збережені |
| D-032 | Усі новини джерел, зокрема міжнародні; стислий виклад зі збереженням суті | Пряма вказівка власника: «новини України» — умовна назва, не географічний фільтр. Скасовує `off_topic` і вимогу 1–2 речень у D-025. Ключові факти, числа, альтернативи, умови, автор заяви й невизначеність мають лишитися; кілька коротких абзаців дозволені |

**D-033 (пряма вказівка власника):** додати ручний скан із зазначенням періоду
та прапорцем для повторного включення вже опублікованих новин, ігноруючи історію.
Має працювати локально й на сервері. Технічний інтерфейс: `run-window --from …
--to … [--ignore-published]`, повний scan/AI/publish. Без прапорця D-012 чинне;
з прапорцем не застосовуються використані ID й пам'ять AI. Окремий ID запиту
зберігає незмінність попередніх доставок. Явні ручні вікна не зсувають планове
покриття; можуть опублікувати історичний період після завершених новіших випусків.
Деталі реалізації й команди — [manual-window.md](manual-window.md).

D-030 уточнено технічно: `group-v4` перевіряє атрибуцію на кшталт
«за даними <канал>», а не будь-який збіг назви каналу з текстом новини.
Наприклад, назва міста може збігатися з назвою джерела.
Відновлення доставки, ізоляція preview, фінальне злиття AI-пачок і аудит пропусків —
виправлення реалізації чинних вимог, описані у [звіті](bugfix-2026-11-11.md).

### Редакторські перевірки не зупиняють випуск (2026-11-12)

| ID | Рішення власника | Наслідок |
| --- | --- | --- |
| D-036 | Оформлення й редакторські побажання не можуть зупинити весь випуск | Погоджено план 2026-11-12. Оформлення (лапки, апострофи, список з одного пункту, вступ до цитати, «Оновлення:») виправляє код; цитата, якої немає в джерелі, прибирається. Зміст (числа з урахуванням «млн/тис» і розрядів, довжина ≤ оригіналу з D-034, «за даними <канал>» з D-030) — одна спроба моделі виправити, далі пункт публікується з лічильником `ai_warning_*`. Невраховані після спроб дописи окремо повторюються по одному; що не вдалося — випуск виходить без них, ID у `ai_unprocessed` (не позначаються використаними, доступні для `run-window`). Зупинка лише коли AI не дав жодної придатної відповіді на пачку або впав API (D-011). Злиття пачок: модель повертає лише групи ID дублікатів, з оригіналів переписуються тільки ці групи; збій злиття лишає перевірені чернетки. | D-037 | Підбірки й меми | Вказівка власника 2026-11-12. Один допис може бути джерелом кількох РІЗНИХ пунктів (підбірка «головне за ранок»); кожна його новина зливається з іншими дописами про ту саму подію. Одна новина — один пункт, ділити її не можна. Допис не може бути водночас у пункті й у виключеннях. Меми й гумор не виключаються: публікуються коротким пунктом про суть мему. Виключення лишаються: реклама (`ad`), привітання/опитування/службові оголошення (`not_news`), повтор без нових фактів (`repeat_without_news`). Промпт `group-v7`; уточнено в `group-v8` (повтор решти новин підбірки, злиття рівно в одну подію). Згадки каналів і медіа як джерел заборонені, як у D-030 |

Картинки (зокрема меми без тексту) не публікуються й моделі не передаються: допис без тексту лишається `unsupported_media`. Допис, частину змісту якого AI не обробив (`ai_unprocessed`), не записується використаним у БД, хоча його інші новини публікуються: ручний перезапуск періоду може обробити залишок. Якщо доставку зупиняє причина для власника (`no_post_rights`, `auth_required`), worker далі повторює спроби (після відновлення прав продовжить сам), але `healthcheck` стає unhealthy, `status` пише «ПОТРІБНА ДІЯ ВЛАСНИКА», у лозі — error `publish_needs_owner_action`. Окремих сповіщень поки немає |
| D-039 | Без «повідомили» й «за словами» | Вказівка власника 2026-11-12 після випуску 12.11. У тексті пунктів немає фраз про те, хто повідомив: «повідомили (про)», «повідомляли», «знову повідомили», «з'явилися повідомлення», «за словами …», «за даними …», «як зазначив …» — це порожні слова, що роздувають пункт. Скасовує дозвіл D-030 на «за словами Зеленського / в ДСНС повідомили». Людину називаємо лише коли новина — її заява чи дія, один раз у заголовку. Невизначеність — словом у самому факті («попередньо», «непідтверджено»). Промпт `group-v9` |
| D-040 | Довга новина — списком | Вказівка власника 2026-11-12. Новина, довша за коротку (`short_source_chars`), з кількома думками завжди подається списком: заголовок — головна думка, далі `▪️` — по одному короткому пункту на кожну логічну думку, без окремого summary. Коротка новина з однією думкою лишається компактною. Приклад — допис про енергоострови в `config/prompts/news-ua.md`. Промпт `group-v10` |
| D-041 | Зміст, а не опис допису | Вказівка власника 2026-11-12 після випуску 12.11. Пункт передає зміст, а не описує допис чи його жанр: без «Допис про», «Жарт про», «Мем про», «Іронія щодо», «Автор пише». «Допис про можливу відставку гендиректора Nvidia» → «Можлива відставка гендиректора Nvidia» (невизначеність оригіналу лишається словом). Меми й іронію переказуємо прямо, як новину. Промпт `group-v11` |
| D-042 | Жарт із фото не публікуємо | Вказівка власника 2026-11-12. Спершу вирішили копіювати короткі іронічні дописи з фото як є; після рев'ю (збій читання джерела блокував доставку, різні фото з однаковим підписом зливались, заміна фото не перевірялась) власник відмовився від цього, щоб не ускладнювати. Фото, як і раніше, не публікуються й моделі не передаються (D-038). Сканер лише позначає, що допис має фото (`has_photo` у payload моделі); короткий жарт/мем, суть якого в картинці, модель виключає як `not_news`. Інші меми й іронія переказуються текстом (D-037, D-041). Промпт `group-v13` |
| D-043 | Без позначки «Оновлення:» | Вказівка власника 2026-11-12. Розвиток уже опублікованої події публікується звичайним пунктом, без «Оновлення:» у заголовку; якщо модель сама його написала, рендер прибирає. `is_update` лишається тільки в метаданих. Змінює D-025. Промпт `group-v12` |

## Технічні defaults і деталізація

- Уточнення реалізації 2026-11-12: `group-v5.1` повторно редагує відхилену
  чернетку з конкретними зауваженнями. AI trace — лише у тимчасовому кеші run;
  CLI показує деталізацію збою. Це діагностика/виправлення retry, не зміна D-034–D-035.
  Фінальне злиття переносить перевірену базу довжини підподій без повторного
  обліку джерел. Час публікації з metadata не вважається вигаданим числом;
  ці зміни виправляють виявлені на реальному кеші хибні відхилення.
- Python 3.13, один worker, Telethon, PostgreSQL 16, JSON/JSONL, Docker Compose.
- Локальний PostgreSQL на хості — порт 5433 (5432 зайнятий crypto-bot). Підключення —
  змінні `POSTGRES_*`; у production пароль через `POSTGRES_PASSWORD_FILE`.
- Інструменти: uv/uv.lock, Typer, pytest/pytest-asyncio, Ruff, mypy;
  asyncio/zoneinfo scheduler, стандартний logging у JSON. Повна таблиця —
  [technology-stack.md](technology-stack.md). Це технічні defaults, не додаткові побажання власника.
- Ключі джерел усередині цільового каналу — `source_channels` і `source_sites`
  (вибір асистента 2026-11-11; власник може перейменувати).
- Промпт цільового каналу — файл `prompt_file` (рекомендовано) або коротке поле `prompt`.
- `filters.exclude_patterns` — прості підрядки без урахування регістру, не regex
  (вибір асистента 2026-11-11: без ризику повільних regex).
- Пакет `src/newsdigest`, збірка hatchling, CLI-коди виходу: 0 — OK, 2 — помилка
  конфігу, 3 — неправильні аргументи.
- Секрети (OpenAI key, Telegram `api_id`/`api_hash`, session) — не в JSON-конфігу, а в secret files.
- `Europe/Kyiv`, шаблон 08:00/21:00; розклади цільових каналів незалежні.
- Кеш: до завершення обробки, максимум 24 години від створення run; 512 MB;
  переживає restart, не входить у backup.
- Власні публікації: 365 днів; пам'ять повторів для моделі: 24 години (D-027); backup: 7 днів.
- `max_chars_per_message=3500`, виклад достатній для збереження суті (D-032),
  нумерація пунктів наскрізна. `max_output_tokens` за замовчуванням не передається
  в API (D-026); явне значення підтримується для сумісності.
- Частини готуються до першого send; кожна має власні `part_key` і `random_id`.
  За часткової доставки підтверджені частини залишаються опублікованими.
- Чистий `preview` одразу очищає кеш; окремий `prepare` зберігає готову серію
  до TTL для подальшого `publish --run-id`. Це усуває суперечність v4 §8/§22.
- Конфігурація schema 4 у JSON. Міграції з YAML schema 3 немає й не потрібно:
  legacy-конфігів не існує.
